### Justification and GX Expectations - raw

**SP-01** - Source contract: without popularity, audio features, genre or the track keys no requirement can be answered.  
- `ExpectTableColumnsToMatchSet(column_set=[14 values], exact_match=False)`

**SP-02** - Profiling: 114,000 rows = 114 genres x ~1,000 tracks. Fewer than half of the expected rows indicates a truncated extraction and would bias every genre baseline; more than 4x indicates a duplicated export.  
- `ExpectTableRowCountToBeBetween(min_value=50000, max_value=500000)`

**SP-03** - Profiling: 0 missing. track_id is the key used to collapse the track x genre grain and to build dim_track.  
- `ExpectColumnValuesToNotBeNull(column=track_id)`

**SP-04** - Profiling: track_id repeats across genres by design (24,259 repeated ids), but 450 exact (track_id, genre) pairs are repeated (894 rows involved, 0.78%). They do not distort results because transformation de-duplicates them; >1% would indicate a faulty export.  
- `ExpectCompoundColumnsToBeUnique(column_list=['track_id', 'track_genre'], mostly=0.99, ignore_row_if=never)`

**SP-05** - Documented Spotify scale (0-100). AR1 averages popularity; one out-of-scale value corrupts the KPI and cannot be repaired automatically.  
- `ExpectColumnValuesToNotBeNull(column=popularity)`
- `ExpectColumnValuesToBeBetween(column=popularity, min_value=0, max_value=100)`

**SP-06** - Documented Spotify scale (0-1); profiling: min 0, max 1.0. AR2 compares their averages across decades.  
- `ExpectColumnValuesToBeBetween(column=danceability, min_value=0, max_value=1)`
- `ExpectColumnValuesToBeBetween(column=energy, min_value=0, max_value=1)`
- `ExpectColumnValuesToBeBetween(column=valence, min_value=0, max_value=1)`

**SP-07** - Domain knowledge: loudness is reported in dB, typically -60..0, slightly positive for heavily mastered tracks. Profiling: min -49.5, max +4.5. A tiny tolerance avoids stopping for isolated sensor artefacts.  
- `ExpectColumnValuesToBeBetween(column=loudness, min_value=-60, max_value=5, mostly=0.999)`

**SP-08** - Profiling: exactly 1 of 114,000 rows has no track_name/artists/album_name. Such a row cannot be matched to a Grammy nomination; transformation drops it and logs the count.  
- `ExpectColumnValuesToNotBeNull(column=track_name, mostly=0.999)`
- `ExpectColumnValuesToNotBeNull(column=artists, mostly=0.999)`

**SP-09** - Profiling: 0 missing, 114 distinct genres. Genre is the grouping attribute of the AR3 KPIs and of the AR1 baseline.  
- `ExpectColumnValuesToNotBeNull(column=track_genre)`

**SP-10** - Profiling: 157 rows (0.14%) have tempo = 0 AND danceability = speechiness = time_signature = 0, i.e. one failure pattern of Spotify's audio analysis; 1 row has duration = 0 (the same record that has no name). A 0 BPM / 0 ms track is impossible, so transformation sets the affected measures to NULL (not imputed) instead of stopping.  
- `ExpectColumnValuesToBeBetween(column=tempo, min_value=0, strict_min=True, mostly=0.995)`
- `ExpectColumnValuesToBeBetween(column=duration_ms, min_value=0, strict_min=True, mostly=0.999)`

**SP-11** - Profiling: only True/False observed (9,747 True). Used as a dim_track attribute only.  
- `ExpectColumnValuesToBeInSet(column=explicit, value_set=[True, False])`

**SP-12** - Monitoring signal: a change in the number of genres suggests a source redesign that would change the genre baseline.  
- `ExpectColumnUniqueValueCountToBeBetween(column=track_genre, min_value=100, max_value=130)`

**GR-01** - Source contract of public.grammy_awards: year, category, nominee, artist, winner, title.  
- `ExpectTableColumnsToMatchSet(column_set=['year', 'title', 'category', 'nominee', 'artist', 'winner'], exact_match=False)`

**GR-02** - Profiling: 4,810 rows over 62 ceremonies (~80 categories each). Below 1,000 rows the extraction is truncated.  
- `ExpectTableRowCountToBeBetween(min_value=1000, max_value=100000)`

**GR-03** - Profiling: 0 missing, range 1958-2019. Year drives the decade dimension; a future or missing year breaks the temporal analysis.  
- `ExpectColumnValuesToNotBeNull(column=year)`
- `ExpectColumnValuesToBeBetween(column=year, min_value=1958, max_value=<run-time value>)`

**GR-04** - Profiling: 0 missing, 638 raw spellings. Category defines dim_category and the music family used by AR3.  
- `ExpectColumnValuesToNotBeNull(column=category)`

**GR-05** - Profiling: 6 missing (0.12%): 4 'Remixer of the Year' and 2 'Best New Country & Western Artist' rows. A record without nominee cannot be identified or matched; transformation drops and logs them.  
- `ExpectColumnValuesToNotBeNull(column=nominee, mostly=0.99)`

**GR-06** - Profiling: 38.3% missing, concentrated in categories that honour songwriters, composers, producers or technical credits (Song Of The Year 70/70, Opera Recording, Album Notes, Instrumental Composition, Country Song...). Missingness is therefore structural, but below 50% the integration pool would be unrepresentative. Transformation recovers part of it from other rows of the same year and title (matching only).  
- `ExpectColumnValuesToNotBeNull(column=artist, mostly=0.5)`

**GR-07** - Source contract: boolean flag. Profiling: 0 missing.  
- `ExpectColumnValuesToNotBeNull(column=winner)`
- `ExpectColumnValuesToBeInSet(column=winner, value_set=[True, False])`

**GR-08** - Profiling: winner = True in 4,810 / 4,810 rows, yet 2019 lists ~5 rows per category (all nominees) while earlier years list ~1 (winners only). The flag is not reliable, therefore NO requirement uses it; rows are treated as 'Grammy recognitions'. This rule is EXPECTED to fail on the current batch and documents the limitation.  
- `ExpectColumnDistinctValuesToContainSet(column=winner, value_set=[True, False])`

**GR-09** - Profiling: 0 duplicated combinations. A duplicated record would create two fact rows for one nomination (grain violation).  
- `ExpectCompoundColumnsToBeUnique(column_list=['year', 'category', 'nominee', 'artist'], ignore_row_if=never)`

**GR-10** - Profiling: 62 distinct years (1958-2019). Gaps would bias decade averages. The dataset is a static historical snapshot, so freshness does not apply; coverage is the temporal check.  
- `ExpectColumnUniqueValueCountToBeBetween(column=year, min_value=60)`
